# AI Research Agent Manager Guide

## Architecture

The app is a full-stack research system:

React dashboard -> Express API -> LangGraph agent -> MCP client -> MCP servers -> external APIs and PostgreSQL.

The frontend handles login, arbitrary research input, high-level activity streaming, source display, tool telemetry, reports, history, and memory. The backend owns authentication, authorization, persistence, SSE, agent orchestration, and evaluation readiness.

## Agent Workflow

LangGraph controls a bounded state machine:

START -> retrieve memory -> plan -> select tool -> execute tool -> evaluate evidence -> repeat or analyze -> extract memory -> END.

Short-term state contains the request, plan, observations, sources, tool calls, and relevant memory. The loop stops when the LLM says evidence is sufficient, a timeout is reached, or `MAX_TOOL_CALLS` is exhausted.

## MCP

The agent never gets arbitrary shell access. It can call only allowlisted MCP tools:

Agent -> MCP client -> MCP server -> tool -> external API/database -> result.

Research MCP exposes `searchWeb`, `searchNews`, and `fetchWebPage`.
GitHub MCP exposes `getRepository`, `listFiles`, `readFile`, `searchCode`, and `getIssues`.
Memory MCP exposes `saveMemory`, `searchMemory`, `getResearchHistory`, and `deleteMemory`.

## Memory

Short-term memory lives in LangGraph state during a run. Long-term memory lives in PostgreSQL with pgvector embeddings generated by the configured embedding provider. The agent searches memory before planning and only saves durable preferences or reusable context after a research run.

## Full Stack Flow

1. User submits a request in React.
2. Express validates authentication and creates a research record.
3. The agent streams safe activity events over SSE.
4. MCP tools gather real web, GitHub, and memory data.
5. Sources and tool calls are persisted.
6. Gemini generates a final report from collected evidence.
7. The report, sources, memory, and telemetry are shown in the dashboard.

## Guardrails

The implementation includes input validation, JWT auth, row-level ownership checks in routes, URL validation, tool allowlisting, configurable tool/time limits, response-size limits, and provider configuration errors. The system fails visibly when APIs are missing or unavailable.
